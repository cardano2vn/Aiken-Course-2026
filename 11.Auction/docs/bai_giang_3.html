1. Bức Tranh Tầng Off-Chain Web3 Trên Cardano EUTxO

Trong kiến trúc Cardano EUTxO, Smart Contract on-chain không chủ động chạy như một tiến trình máy chủ. Nó chỉ đóng vai trò người thẩm định (Validator) khi có một giao dịch gửi đến.

Nhiệm vụ của tầng Off-Chain là cầu nối biến các thao tác của người dùng trên giao diện web thành các giao dịch EUTxO hợp lệ, bao gồm: truy vấn UTxO sàn qua Blockfrost, đóng gói Double-CBOR, chuẩn hóa Plutus JSON CIP-57, cấp ngân sách tính toán tất định, cân bằng phí và ký gửi lên blockchain an toàn.

2. Kỹ Thuật Chuẩn Hóa Double-CBOR & Triệt Tiêu Lỗi Code 3116

this.scriptCbor = applyParamsToScript(
  blueprint.validators[0].compiledCode,
  [],
  "JSON"
);
this.scriptAddress = this.getScriptAddress(this.scriptCbor);
Cardano Node Error 3116:
{"code":3116,"message":"Some Plutus scripts in the witness set or in an output are invalid. Scripts must be well-formed flat-encoded Plutus scripts, CBOR-encoded. Yes, there's a double binary encoding..."}

Khi biên dịch bằng aiken build, chuỗi compiledCode trong plutus.json chỉ được bọc 1 lớp CBOR đơn. Khi nạp vào MeshJS, SDK bóc mất lớp CBOR này, để lộ chuỗi Flat bytecode trần trụi. Khi gửi lên mạng Conway Ledger, Node kiểm tra witness set thấy thiếu lớp bọc CBOR ByteString hợp lệ, lập tức trả về lỗi 3116. Bằng cách gọi applyParamsToScript(..., [], 'JSON') với mảng tham số rỗng, SDK tự động bọc thêm một lớp CBOR thứ hai (Double-CBOR) chuẩn xác.

3. Chuẩn Hóa Plutus JSON (CIP-57) & Hàm safePlutusJson

function safePlutusJson(obj: unknown): any {
  return JSON.parse(
    JSON.stringify(obj, (_, v) => {
      if (typeof v === "bigint") return Number(v);
      if (v && typeof v === "object" && !Array.isArray(v)) {
        const ctor = (v as any).constructor !== undefined ? Number((v as any).constructor) : undefined;
        const alt = (v as any).alternative !== undefined ? Number((v as any).alternative) : undefined;
        const tag = ctor !== undefined ? ctor : alt;
        if (tag !== undefined && "fields" in (v as any)) {
          return { ...v, alternative: tag, constructor: tag };
        }
      }
      return v;
    })
  );
}

Trong chuẩn CIP-57, đối tượng dữ liệu được định danh bằng trường constructor. Nhưng MeshTxBuilder nội bộ lại đi tìm data.alternative để gọi BigInt(data.alternative). Khi dùng các helper như pubKeyAddress(), trường alternative bị undefined, gây ra lỗi Runtime làm sập ứng dụng. Hàm safePlutusJson duyệt đệ quy và đồng bộ song song cả hai trường constructor: tag và alternative: tag, đồng thời chuyển đổi an toàn bigint thành số nguyên tiêu chuẩn.

4. Quản Trị Execution Budget: Vô Hiệu Hóa Evaluator Tự Động & Lỗi 3136

if (this.mesh.evaluator) {
  console.log("[AuctionContract] Disabling evaluator — manual budgets will be used from txInRedeemerValue calls.");
  (this.mesh as any).evaluator = undefined;
}

Khi Mesh thực hiện Coin Selection, nó tạo ra các bản nháp giao dịch tạm thời (chưa cân bằng phí). Nếu evaluator gửi bản nháp này qua Blockfrost/Ogmios, Ogmios sẽ từ chối ở Phase-1. Nếu SDK bắt lỗi rồi điền budget ước lượng giả định, giao dịch submit thật sẽ bị lỗi 3136 (Unexpected Script Failure). Vô hiệu hóa evaluator giúp chúng ta sử dụng trực tiếp Manual Budget tất định từ benchmark on-chain (ví dụ nhánh Close cấp `{ mem: 700000, steps: 200000000 }`), đảm bảo tốc độ dựng nhanh và xác suất submit thành công 100%.

5. Mổ Xẻ 5 Hàm Giao Dịch Trong Lớp `AuctionContract`

5.1. `startAuction`: Niêm Yết NFT & Khóa Cọc min-ADA

startAuction = async (nftAssets: Asset[], minBidInLovelace: number, deadlineMs: number, minIncrementInLovelace = 1_000_000) => {
  deadlineMs = Math.floor(deadlineMs / 1000) * 1000;
  if (!nftAssets || nftAssets.length === 0) throw new Error("Cần ít nhất 1 NFT.");
  if (minBidInLovelace <= 0) throw new Error("minBid phải lớn hơn 0.");
  if (deadlineMs <= Date.now()) throw new Error("Deadline phải nằm trong tương lai.");

  this.mesh.reset();
  const { utxos, walletAddress } = await this.getWalletInfoForTx();
  const cleanNftAssets = nftAssets.filter((a) => a.unit !== "lovelace" && a.unit !== "");

  const outputDatum = auctionDatum(walletAddress, deadlineMs, minBidInLovelace, minIncrementInLovelace, cleanNftAssets);

  await this.mesh
    .txOut(this.scriptAddress, cleanNftAssets)
    .txOutInlineDatumValue(outputDatum, "JSON")
    .changeAddress(walletAddress)
    .selectUtxosFrom(utxos)
    .complete();

  return this.mesh.txHex;
};

Hàm thực hiện lọc sạch NFT để loại bỏ lovelace rác khỏi mảng tài sản, đảm bảo khớp với kiểu MValue trên Aiken. Người dùng không cần tự cộng 2 ADA cọc vào output: MeshTxBuilder tự động tính toán lượng min-UTxO Lovelace theo quy định của sổ cái và bổ sung vào output của script.

Quy tắc hoàn tiền trong `bid`:
- Lượt đầu: Hoàn trả lại 2 ADA cọc ban đầu cho Seller.
- Các lượt sau: Hoàn trả tức thời 100% tiền cho bidder trước đó (Atomic Refund).
- Giới hạn thời gian: Cận trên đặt bằng Math.min(deadlineSlot - 2, currentSlot + 600) để đảm bảo giao dịch chỉ có hiệu lực trước khi hết hạn.

5.3. `update`, `cancel` & `close`

  • update: Bắt buộc chữ ký sellerPkh, chỉ sửa khi chưa có ai bid, và bảo toàn nguyên vẹn NFT vào script mới.
  • cancel: Hoàn trả 100% tài sản trong UTxO về ví Seller, hoàn toàn không ràng buộc deadline.
  • close: Bắt buộc lowerBoundSlot = deadlineSlot + 1 để thỏa mãn is_entirely_after, tự động phân phối tiền cho Seller và trao NFT cho Winner.
