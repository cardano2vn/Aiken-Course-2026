Module 11: English Auction Smart Contract (Sàn Đấu Giá Kiểu Anh Phi Tập Trung)
Mục tiêu bài giảng: Đi sâu mổ xẻ từng dòng code Aiken trong validators/auction.ak, làm rõ triết lý thiết kế EUTxO State Machine, đối chiếu các kịch bản tấn công và làm chủ ma trận 19 Unit Tests on-chain.

1. Giới Thiệu & Phương Pháp Tiếp Cận Mã Nguồn

Sau khi đã nắm vững nền tảng kiến trúc ở Bài 11.1, bài học này đi sâu vào việc phân tích trực tiếp từng dòng code trong validators/auction.ak. Mục tiêu là hiểu rõ lý do của từng điều kiện kiểm tra, các kịch bản tấn công tương ứng và đối chiếu với 19 bài Unit Test on-chain.

2. Cấu Trúc Thư Mục & Phân Tích Chi Tiết Các Thư Viện Imports (Dòng 1-9)

1  use aiken/collection/list

Các thư viện phụ thuộc phục vụ những nhiệm vụ cụ thể:

  • list (Dòng 1): Cung cấp hàm list.filter lọc chính xác các output gửi về lại Script Address.
  • interval (Dòng 2): Quản lý thời gian qua tx.validity_range bằng is_entirely_before (trước deadline) và is_entirely_after (sau deadline).
  • cardano/* (Dòng 3-5): Định kiểu địa chỉ ví, token đa tài sản, chuyển đổi tiền ADA Lovelace và tham chiếu giao dịch EUTxO.
  • vodka_* (Dòng 6-9): Gói trợ thủ tối ưu: inputs_at đếm số UTxO tại script, key_signed kiểm tra chữ ký số, và value_geq so sánh đa tài sản.

3. Phân Tích Chi Tiết Từng Dòng Code: Khai Báo Kiểu Dữ Liệu

3.1. Kiểu `POSIXTime`, `MValue` & Cấu trúc `BidState`

11 pub type POSIXTime = Int

14 pub type MValue = Pairs<PolicyId, Pairs<AssetName, Int>>

22 pub type BidState {
23   BidState {
24     bidder: Address, // Địa chỉ người đặt giá (hỗ trợ stake key)
25     amount: Int,     // Số tiền đặt (Lovelace)
26   }
27 }

Kiểu dữ liệu BidState sử dụng Address thay vì ByteArray (PubKeyHash) để đảm bảo hỗ trợ đầy đủ ví có Stake Key và Script Address của các dApp khác trên Cardano.

3.2. Cấu trúc `AuctionDatum` & `AuctionRedeemer`

38 pub type AuctionDatum {
39   AuctionDatum {
40     seller: Address,
41     deadline: POSIXTime,
42     min_bid: Int,
43     min_increment: Int,
44     nft: MValue,
45     highest_bid: Option<BidState>,
46   }
47 }

52 pub type AuctionRedeemer {
53   MkBid { bidder: Address, amount: Int }
54   Update { new_price: Int }
55   Cancel
56   Close
57 }

Trong AuctionDatum, trường min_increment đảm bảo bước giá tối thiểu bắt buộc giữa các lượt đặt giá, ngăn chặn hành vi quấy rối tăng 1 Lovelace. Trường highest_bid: Option<BidState> biểu diễn chính xác trạng thái chưa có ai bid (None) hoặc đã có người dẫn đầu (Some).

4. Mổ Xẻ Từng Dòng Code: Validator `auction`

4.1. Khởi Tạo & Mở Gói Datum An Toàn

66 validator auction {
67   spend(
68     datum_opt: Option<AuctionDatum>,
69     redeemer: AuctionRedeemer,
70     input: OutputReference,
71     tx: Transaction,
72   ) {
73     expect Some(datum) = datum_opt

Dòng 73 expect Some(datum) = datum_opt đóng vai trò người gác cổng, ngăn chặn hoàn toàn việc chi tiêu các UTxO không có Datum hợp lệ gửi vào Script Address.

4.2. Nhánh 1: `MkBid` — Đặt Giá Mới, Hoàn Cọc & Atomic Refund (Dòng 79-135)

79       MkBid { bidder, amount } -> {
80         expect Some(own_input) = find_input(tx.inputs, input)
81         let own_address = own_input.output.address
82
83         // a. Chống Double Satisfaction: Chỉ tiêu thụ duy nhất 1 UTxO từ hợp đồng trong TX
84         let is_only_one_input_from_script =
85           when inputs_at(tx.inputs, own_address) is {
86             [_] -> True
87             _ -> False
88           }
89
90         // b. Kiểm tra thời gian: Phải diễn ra TRƯỚC deadline
91         let is_before_deadline =
92           interval.is_entirely_before(tx.validity_range, datum.deadline)
93
94         // c. Kiểm tra giá thầu: Lượt đầu >= min_bid, lượt sau >= prev_bid + min_increment
95         let is_valid_bid_amount =
96           when datum.highest_bid is {
97             None -> amount >= datum.min_bid
98             Some(prev_bid) -> amount >= prev_bid.amount + datum.min_increment
99           }
100
101        // d. Hoàn cọc min-ADA cho Seller (lượt đầu) HOẶC hoàn tiền cho bidder cũ (lượt sau)
102        let is_refund_valid =
103          when datum.highest_bid is {
104            None -> {
105              let initial_deposit = lovelace_of(own_input.output.value)
106              get_all_value_to(tx.outputs, datum.seller)
107                |> value_geq(from_lovelace(initial_deposit))
108            }
109            Some(prev_bid) ->
110              get_all_value_to(tx.outputs, prev_bid.bidder)
111                |> value_geq(from_lovelace(prev_bid.amount))
112          }
113
114        // e. Đảm bảo DUY NHẤT 1 UTxO tiếp nối tại Script Address
115        expect [continuing_output] =
116          list.filter(tx.outputs, fn(out) { out.address == own_address })
117
118        expect InlineDatum(raw_datum) = continuing_output.datum
119        expect output_datum: AuctionDatum = raw_datum
120
121        // f. Datum mới cập nhật highest_bid, giữ nguyên các trường khác
122        let is_datum_updated_correctly =
123          output_datum.seller == datum.seller && output_datum.deadline == datum.deadline && output_datum.min_bid == datum.min_bid && output_datum.min_increment == datum.min_increment && output_datum.nft == datum.nft && output_datum.highest_bid == Some(
124            BidState { bidder, amount },
125          )
126
127        // g. UTxO mới phải chứa đúng NFT và số tiền Lovelace mới đặt
128        let expected_script_value =
129          from_asset_list(datum.nft)
130            |> assets.merge(from_lovelace(amount))
131        let is_value_locked = value_geq(continuing_output.value, expected_script_value)
132
133        is_only_one_input_from_script && is_before_deadline && is_valid_bid_amount && is_refund_valid && is_datum_updated_correctly && is_value_locked
134      }
Ba trụ cột bảo mật trong `MkBid`:
1. Chống Double Satisfaction: Ép buộc đúng 1 UTxO từ script trong mỗi transaction bằng cú pháp [_].
2. Hoàn cọc Seller & Atomic Refund: Lượt đầu hoàn trả 2 ADA cọc cho Seller; các lượt sau hoàn trả tức thời 100% tiền cho bidder trước đó.
3. Bảo vệ UTxO tiếp nối: Sử dụng list.filter kết hợp expect [continuing_output] loại bỏ hoàn toàn khả năng tạo script output giả mạo.

4.3. Nhánh 2: `Update` & Nhánh 3: `Cancel` & Nhánh 4: `Close`

      // UPDATE: Chỉ Seller sửa giá khi CHƯA có ai bid, BẢO TOÀN NFT
      Update { new_price } -> {
        ...
        let expected_script_value = from_asset_list(datum.nft)
        let is_asset_preserved = value_geq(continuing_output.value, expected_script_value)
        is_signed_by_seller && is_no_bid_yet && is_before_deadline && is_datum_updated_correctly && is_asset_preserved
      }

      // CANCEL: Seller hủy phiên rút toàn bộ tài sản, KHÔNG RÀNG BUỘC DEADLINE
      Cancel -> {
        ...
        let is_seller_refunded = get_all_value_to(tx.outputs, datum.seller) |> value_geq(own_input.output.value)
        is_signed_by_seller && is_no_bid_yet && is_seller_refunded
      }

      // CLOSE: Chốt phiên SAU DEADLINE, chuyển tiền cho Seller và NFT cho Winner
      Close -> {
        ...
        let is_after_deadline = interval.is_entirely_after(tx.validity_range, datum.deadline)
        // Seller nhận highest_bid.amount, Winner nhận NFT + min-UTxO ADA
      }
